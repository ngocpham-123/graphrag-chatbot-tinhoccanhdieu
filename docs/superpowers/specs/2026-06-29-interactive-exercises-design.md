# Interactive Exercises — Design

**Date:** 2026-06-29
**Status:** Approved (ready for implementation planning)

## Summary

Let students **try** the exercises ("Bài tập") and get **feedback plus a model
answer** for each attempt. The same interactive "exercise runner" appears in two
places:

1. In the **📚 Thư viện** Bài tập tab — each exercise can be attempted inline.
2. In the **QA chatbot** — when an answer was produced from a GraphDB query that
   returned exercises, two buttons appear under the answer offering to spin up the
   same inline exercise runner.

The textbook ingest contains **no stored answers** for exercises (assessment items
carry only `hasRawText` and a title; questions are open-ended free-response in
Vietnamese). Therefore feedback and the "true answer" are **generated by the LLM**
(`gpt-4.1-mini`, already used by the app), **grounded** in the exercise's own lesson
content. The feature is additive; the existing QA pipeline and curriculum browser
keep working.

## Goals

- A student types a free-text answer to an exercise and receives:
  - a verdict (`correct | partial | incorrect`, shown as
    **Chính xác / Gần đúng / Chưa chính xác**),
  - short Vietnamese feedback on their attempt,
  - a lesson-grounded model answer ("Đáp án mẫu").
- One reusable widget + one grading endpoint serve both the Library and the chatbot.
- Chatbot offers the runner only when an answer actually surfaced exercises.

## Non-Goals (YAGNI)

- No saved attempts, progress, scores, or attempt history (re-submitting simply
  re-grades). No accounts/auth. No new database.
- No multiple-choice / auto-graded option matching (data has none).
- No rich-text editor; plain `<textarea>`.
- No configurable rubric. Grading is a single grounded prompt.
- The "true answer" is explicitly an AI-generated, lesson-grounded **model answer**,
  not an authoritative textbook key (the textbook ships none). Wording in the UI
  reflects this ("Đáp án mẫu").

## Data Facts (verified against `D:\Downloads\CD-Sparql`)

- Assessment items (`ex:Exercise`, `ex:ReviewQuestionItem`, `ex:PracticeExercise`,
  `ex:AppliedTask`, `ex:PracticeTask`, `ex:PracticalInstruction`, `ex:ProjectTask`,
  `ex:Activity`) have `rdfs:label` (title), `ex:hasRawText` (the question), and
  `ex:belongsToLesson`. No answer/option/solution predicates exist anywhere in the
  graph.
- Exercises are open-ended free response (e.g. "Em hãy nêu một ví dụ…",
  "Tạo lối tắt đến…"), so grading is LLM-based on free text, not key matching.

## Architecture

One grading engine, two front-end surfaces, one shared widget.

- **`backend/app/services/exercise_service.py` (new)** — the grading engine.
  - `get_exercise(exercise_id) -> dict | None` — resolve `ex:{id}` →
    `{id, type, title, text, lessonId}` via SPARQL; `None`/raise if not an
    assessment item.
  - `grade_exercise(exercise_id, user_answer) -> dict` — resolve the exercise,
    build grounding context from `curriculum_service.lesson_detail(lessonId)`, call
    the grading LLM, return `{verdict, feedback, modelAnswer}`.
  - `extract_exercises_from_rows(sparql, rows) -> list[dict]` — given a generated
    SPARQL string and its rdflib result rows, return `[{id, type, title, text}]`
    when the rows describe assessment items (detected by the presence of `item`,
    `kind`/type, and `text` result variables and assessment-class references in the
    query); otherwise `[]`. Pure function, no LLM, no network — unit-testable.
  - Reuses `curriculum_service` (`local_name`, `_validate_id`, `_run_select`,
    `lesson_detail`, `CurriculumError`, `NotFoundError`) — no duplicate SPARQL
    helpers. Uses a module-level `ChatOpenAI(model="gpt-4.1-mini", temperature=0)`.
- **`backend/app/routers/exercises.py` (new)** — `POST /api/exercises/grade`.
- **`frontend/exercise.js` (new, shared)** — `mountExerciseRunner(container,
  exercises)`; included by both `frontend/library.html` and `frontend/index.html`.
- **Library**: `library.js` Bài tập tab adds a per-exercise "Làm bài" toggle that
  mounts the runner inline.
- **Chatbot**: `ChatResponse` gains `exercises`; `orchestrator` passes them through;
  `app.js` shows the two-button offer and mounts the runner.

## Grading Engine + Endpoint

`POST /api/exercises/grade`
- Request: `{ "exerciseId": "<iri-localname>", "userAnswer": "<text>" }`.
- The client sends only the exercise id (validated `^[A-Za-z0-9_]+$`) and the
  answer. The server resolves the question text + lesson from GraphDB so grading is
  consistent and not client-spoofable.
- Response: `{ "verdict": "correct|partial|incorrect", "feedback": "<vi>",
  "modelAnswer": "<vi>" }`.

Grounding context (compact, capped ≈3–4k chars) assembled from
`lesson_detail(lessonId)`: lesson title, objectives, section titles + paragraph
text, concept definitions, and summary. The exercise text is included verbatim.

Grading prompt (Vietnamese, temperature 0, JSON output): instructs the model to act
as a Tin học teacher, evaluate the student's answer against the lesson content and
the exercise, and return strict JSON with `verdict`, `feedback`, `modelAnswer`. The
service parses the JSON; on parse failure it falls back to `verdict="partial"` with
the raw text as feedback (never 500s on a malformed model reply). All returned
strings are NFC-normalized for consistency with the rest of the API.

Errors:
- Unknown / non-assessment `exerciseId` → 404.
- Empty/blank `userAnswer` → 400.
- GraphDB or OpenAI failure → 503 (mapped from `CurriculumError` / an LLM error).

## Shared Widget (`exercise.js`)

`mountExerciseRunner(container, exercises)` with `exercises = [{id, title, text}]`.
For each exercise it renders: the question text, a `<textarea>`, and a **"Nộp bài"**
button. On submit it POSTs `{exerciseId: id, userAnswer}` to
`/api/exercises/grade`, disables the button while pending, then renders the verdict
(color-coded: green/amber/red), the feedback, and an **"Đáp án mẫu"** box, plus a
**"Làm lại"** button that clears the result for another attempt. Empty answers are
blocked client-side with a hint. All API-derived and user text is HTML-escaped
before insertion (reuse the page's `esc()` pattern; `exercise.js` defines its own
`escHtml` to stay self-contained). Network/server errors render an inline retry
message.

## Library Integration (Bài tập tab)

`library.js renderAssessments` keeps showing each assessment's title + text, and
adds a **"✍️ Làm bài"** toggle button per card. Clicking it mounts the runner
inline (in a container under that card) for that single exercise
(`mountExerciseRunner(el, [{id, title, text}])`); clicking again hides it.

## Chatbot Integration

- **Detection / extraction:** the assessment SPARQL guidance in
  `chatgpt_service.SPARQL_GENERATION_PROMPT` is extended so assessment queries also
  project the item IRI (`?item`) alongside `?kind`/`?title`/`?text`.
  `FormattedGraphDBQAChain.retrieve_context` is extended to return a 4-tuple
  `(context, sparql, figure_urls, exercises)`, where `exercises` is computed by
  `exercise_service.extract_exercises_from_rows(sparql, rows)` over the same rows it
  already fetched. The single caller (`orchestrator.answer_question`) is updated to
  the 4-tuple. `extract_exercises_from_rows` turns assessment rows into
  `[{id, type, title, text}]`.
- **Plumbing:** `orchestrator.answer_question` returns `exercises` in its result;
  `ChatResponse` gains `exercises: list | None`; `chat.py` includes them in the
  response (and in stored history so they survive a reload, optional).
- **UI:** in `app.js`, after appending an assistant answer, if `data.exercises` is
  non-empty, render a panel under the message: *"Bạn có muốn thử làm các bài tập
  này không?"* with **[▶ Làm thử]** and **[Bỏ qua]**. "Làm thử" replaces the panel
  with `mountExerciseRunner(panel, data.exercises)`; "Bỏ qua" removes the panel. The
  panel is absent when no exercises were found.
- `index.html` includes `exercise.js` before `app.js`; both pages bump their asset
  cache version.

## Data Flow

1. Student opens an exercise (Library card or chat offer) → widget shows question +
   textarea.
2. Submit → `POST /api/exercises/grade {exerciseId, userAnswer}`.
3. Service resolves exercise + lesson, grounds via `lesson_detail`, calls LLM,
   returns verdict/feedback/modelAnswer.
4. Widget renders the result; "Làm lại" allows another attempt.

## Testing

- **`exercise_service`** (integration, real OpenAI, temp 0):
  - `get_exercise` for a known id (e.g. `l1_ex2`) returns its text + `lessonId`;
    unknown id raises `NotFoundError`.
  - `grade_exercise` on a clearly-correct answer to `l1_ex2` ("đầu vào là dữ liệu,
    đầu ra là thông tin") is **not** `incorrect`; on an empty/irrelevant answer is
    **not** `correct`; `feedback` and `modelAnswer` are non-empty; `verdict` is in
    the allowed set.
  - `extract_exercises_from_rows` (pure, no network): rows with `item`/`kind`/`text`
    variables for assessment classes → non-empty list with correct ids/text;
    non-assessment rows → `[]`.
- **Router** (FastAPI `TestClient`, minimal app mounting only the exercises router):
  `POST grade` → 200 with the three keys; unknown id → 404; empty answer → 400.
- **Frontend**: a page-serving test asserting `index.html`/`library.html` reference
  `exercise.js`; manual browser click-through for both surfaces.

## Deployment

Code-only + new static file (`exercise.js`); no new dependency (reuses
`langchain_openai`, `SPARQLWrapper`), no index rebuild, no image rebuild. Grading
makes live OpenAI calls (same key/model the chatbot already uses). Deployable via
`git pull` (uvicorn `--reload`).

## Future / Optional (not in v1)

- Persisted attempts/progress (would justify the Postgres deferred in the library
  design).
- Per-exercise hints or step-by-step Socratic feedback.
